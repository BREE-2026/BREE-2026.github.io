System Calibration系统标定

Calibrate arms when hardware is first installed or changed. For daily startup, verify the H pose, restore the saved camera image controls and compare all three cameras with the existing reference images.首次安装或硬件变化后标定机械臂；日常开机则验证 H 位、恢复已保存的相机图像参数，并将三台相机与已有参考图对齐。

Run the commands below from the BREE-v1 repository root.以下命令均在 BREE-v1 仓库根目录运行。

Keep the reference保留参考基准

Daily checks read the existing references. Run save-reference only when deliberately defining a new installation baseline; keep the previous baseline for comparison.日常检查读取已有参考文件。仅在需要重新定义安装基准时执行 save-reference，并保留原基准以便对照。

1 · Fixture midpoint calibration1 · 限位夹具中点标定

Complete SO-101 motor numbering and assembly first. Secure one arm in the physical fixture, verify its port and leave space for preview motion. Repeat for each arm using the table.先完成 SO-101 舵机编号与装配。将一条机械臂固定到物理限位架，核对端口，并为预览运动留足空间。按表逐臂操作。

Use both views to check that the arm is fully seated in the fixture before reading calibration values. Click either photo to inspect the original image.结合两张实拍图，确认机械臂各关节已在夹具中就位，再读取标定数值。点击图片可查看原图。

To compute and inspect values without writing calibration, first run the command with --dry-run instead of --preview-ranges. Range preview temporarily writes calibration to the motors and moves joints: after computation, remove the fixture before accepting the preview prompt. The final save prompt is separate from permission to preview.仅计算并检查数值时，先将命令中的 --preview-ranges 替换为 --dry-run，此时不写入标定。范围预览会临时向舵机写入标定并移动关节；计算完成后，先取下夹具，再同意运动预览。最终保存确认与预览确认是两个步骤。

Arm机械臂Device类型Port端口Calibration ID标定 ID
Left follower左从臂follower/dev/ttyACM0follower_arm_left
Right follower右从臂follower/dev/ttyACM1follower_arm_right
Left leader左主臂leader/dev/ttyACM2leader_arm_left

bash
python BREE/robot_calibration/fixture_midpoint_auto_calibrate.py \
  --device follower \
  --port /dev/ttyACM0 \
  --id follower_arm_left \
  --preview-ranges

Inspect the values and movement directions before answering y at the write prompt. The script backs up existing calibration as .json.bak. Follower files live under ~/.cache/huggingface/lerobot/calibration/robots/so_follower/; leader files under ~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/.核对数值与运动方向后，在写入提示中输入 y。已有标定会备份为 .json.bak。从臂文件位于 ~/.cache/huggingface/lerobot/calibration/robots/so_follower/，主臂位于 ~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/。

Calibration without range preview不进行范围预览的标定

If mechanics and directions have already been verified, omit --preview-ranges. This still computes and writes a new calibration after confirmation; it is not a daily check. For a calculation-only check, add --dry-run to this command.已确认机械结构与运动方向时，可省略 --preview-ranges。此命令仍会在确认后重新计算并写入标定，不用于日常检查。仅计算、不写入时，在此命令末尾增加 --dry-run。

bash
python BREE/robot_calibration/fixture_midpoint_auto_calibrate.py \
  --device follower \
  --port /dev/ttyACM0 \
  --id follower_arm_left

Wrist-roll coordinates腕部滚转坐标说明

The fixture script uses an asymmetric wrist_roll range of −270° … +45° relative to the fixture pose. With the default 4096-count encoder, the saved range is approximately 0 … 3583 and the fixture pose is near 3071 ticks. Do not replace this fixture position with the range midpoint. The default H-home wrist offset is −180° from the fixture; the printed LeRobot control angle uses a different coordinate origin.夹具脚本中，wrist_roll 相对夹具姿态采用 −270° … +45° 的非对称范围。默认 4096 计数编码器对应保存范围约 0 … 3583，夹具位置约 3071 ticks，不能用范围中点替代。H 位默认腕部偏移为相对夹具 −180°；日志中的 LeRobot 控制角度采用另一坐标原点。

If the script reports wrist_roll installation is out of range, it aborts without writing calibration. Power off, adjust the installation by the direction and minimum angle reported, then reseat the arm in the fixture and retry.若提示 wrist_roll installation is out of range，脚本会终止且不写入标定。断电后按提示方向与最小角度调整安装齿位，再将机械臂放回夹具重新标定。

3 · Standardize camera parameters3 · 相机参数统一

Use the same capture format for the global, left-wrist and right-wrist cameras, then tune each camera under the fixed experiment lighting for consistent color and brightness. Retain each camera’s settings for collection and evaluation.全局、左腕、右腕相机使用统一的采集格式，再在固定实验光照下逐台调节，使三路画面的色彩与亮度一致。采集和评测均沿用各相机保存的参数。

Parameter参数Target / procedure统一要求 / 操作
Capture format采集格式640 × 480 · 30 fps · MJPG
Device mapping设备映射Example: global / left wrist / right wrist = /dev/video0 / /dev/video2 / /dev/video4. Verify live views after reconnecting.示例：全局 / 左腕 / 右腕 = /dev/video0 / /dev/video2 / /dev/video4。重连后按实时画面核对。
White balance and exposure白平衡与曝光Turn AUTO WB and AUTO EXP off after settling, then fine-tune and save the manual values.待画面稳定后，将 AUTO WB 与 AUTO EXP 关闭，再微调并保存手动值。
Other image controls其他图像参数Adjust supported brightness, contrast, saturation, gamma, gain and sharpness controls per camera. Match the appearance of the same reference object; values may differ between cameras.按各相机支持情况调节亮度、对比度、饱和度、伽马、增益和锐度。用同一参照物匹配画面效果，各相机数值可不同。

First setup · tune and save首次设置 · 调节并保存

The repository provides BREE/camera_calibration/calibrate_three_camera_white_balance.py, which opens a combined preview and one control window per camera. Run it on Linux with a desktop display and GUI-enabled OpenCV, in the installed BREE environment. Close other camera previews, recording and evaluation processes first. On Ubuntu / Debian, install the V4L2 utility if needed:仓库提供 BREE/camera_calibration/calibrate_three_camera_white_balance.py，可打开三路合并预览与各相机的参数窗口。在已安装 BREE 的 Linux 桌面环境运行，OpenCV 需支持 GUI。先关闭占用相机的其他预览、录制和评测进程。Ubuntu / Debian 如缺少 V4L2 工具，先安装：

bash
sudo apt install v4l-utils
python BREE/camera_calibration/calibrate_three_camera_white_balance.py \
  --devices /dev/video0 /dev/video2 /dev/video4 \
  --names GLOBAL LEFT_WRIST RIGHT_WRIST \
  --width 640 \
  --height 480 \
  --fps 30 \
  --output outputs/camera_check/camera_image_controls.json
  • Keep the lights and background fixed. Show the same neutral reference object to each camera and adjust WB TEMP, EXPOSURE TIME and the other available sliders until color and brightness are consistent, without washed-out highlights or motion blur.固定灯光与背景，让各相机拍到同一中性参照物。调节 WB TEMP、EXPOSURE TIME 及其他可用滑条，使色彩和亮度一致，避免高光过曝与运动拖影。
  • Set both auto sliders to 0. Only controls exposed by the driver appear. Focus the preview and press S to read back and save the current driver values; press Q or Esc to quit and release all cameras.将两个自动模式滑条设为 0；窗口仅显示驱动支持的控制项。聚焦预览窗口，按 S 读取并保存驱动当前值，按 Q 或 Esc 退出并释放相机。
  • The saved JSON stores image controls keyed by device path. Resolution, frame rate and MJPG remain separate settings in preview, collection and evaluation commands or configurations.保存的 JSON 按设备路径记录图像控制参数。分辨率、帧率和 MJPG 仍需在预览、采集与评测命令或配置中分别保持一致。

Daily startup · restore and verify日常开机 · 恢复并核对

After verifying device mapping, restore the locally tuned file with BREE/camera_calibration/apply_camera_image_controls.py. Replace the path below if your baseline is stored elsewhere:核对设备映射后，用 BREE/camera_calibration/apply_camera_image_controls.py 恢复本机调好的配置。若基准保存在其他位置，替换下方文件路径：

bash
python BREE/camera_calibration/apply_camera_image_controls.py \
  outputs/camera_check/camera_image_controls.json \
  --force-manual \
  --max-exposure-time 300

for camera in /dev/video0 /dev/video2 /dev/video4; do
  v4l2-ctl -d "$camera" --get-fmt-video --get-parm --list-ctrls
done

The restore script disables dynamic frame rate when supported, skips unsupported controls and limits saved exposure_time_absolute values to 300 by default to help preserve 30 fps. This is a driver control value. Review any clamp messages, then check brightness and actual stream cadence. Some cameras reset controls when streaming starts: check again after opening the intended stream and reapply from another terminal if needed.恢复脚本会在设备支持时关闭动态帧率，跳过不支持的控制项，并默认将保存的 exposure_time_absolute 上限设为 300，以帮助维持 30 fps；这是驱动控制值。若出现限幅提示，需重新检查亮度与实际出帧速度。部分相机在启动视频流时会重置参数：打开目标视频流后再次核对，必要时从另一终端重新应用。

Check the saved baseline检查保存的基准

The repository’s root camera_image_controls.json contains example values with automatic exposure enabled on all three cameras and automatic white balance enabled on the global camera. Tune and save your own baseline. After reconnecting, update device-path keys if the camera mapping changed. Continue with reference-image alignment once image controls are stable.仓库根目录的 camera_image_controls.json 是示例配置，其中三台相机仍开启自动曝光，全局相机还开启自动白平衡。请调节并保存本机基准；重连后若相机映射变化，应同步更新 JSON 中的设备路径。参数稳定后，再继续参考图对齐。

4 · Align the global camera4 · 全局相机对齐

bash
python BREE/camera_calibration/global_camera_reference_calibrate.py check \
  --camera /dev/video0 \
  --width 640 \
  --height 480 \
  --fps 30 \
  --fourcc MJPG \
  --camera-warmup-s 2 \
  --web-host 127.0.0.1 \
  --web-port 8092 \
  --preview-fps 15 \
  --max-candidates 8 \
  --max-angle-deg 12 \
  --min-length-ratio 0.35 \
  --reference BREE/camera_reference/global_image/reference.json \
  --output-dir outputs/camera_check/global_image

Open http://127.0.0.1:8092. Match the beam, arm bases, table edges and fixed screws in the 50/50 overlay. The command normally homes both followers first; add --skip-robot-home to inspect the camera without connecting the arms. Close this check before starting the right-wrist preview on the same port.打开 http://127.0.0.1:8092，在 50/50 叠加画面中对齐横梁、机械臂底座、桌边和固定螺丝。默认会先将两条从臂移动到 H 位；仅检查相机、不连接机械臂时增加 --skip-robot-home。右腕预览使用同一端口，启动前先关闭全局检查。

5 · Align both wrist cameras5 · 两台腕部相机对齐

Place the arms at the reference pose before using camera-only mode. It does not move or lock an arm. Verify indices from live views, then run each check separately.在纯相机模式下先将机械臂置于参考姿态；此模式不会移动或锁定机械臂。按实时画面核对编号后，分别运行以下检查。

bash
python BREE/camera_calibration/wrist_camera_reference_calibrate.py check \
  --camera-only \
  --camera /dev/video2 \
  --width 640 \
  --height 480 \
  --fps 30 \
  --fourcc MJPG \
  --camera-warmup-s 2 \
  --reference BREE/camera_reference/overlay/left_wrist/reference.json \
  --output-dir outputs/camera_check/overlay/left_wrist \
  --live \
  --web-host 127.0.0.1 \
  --web-port 8091 \
  --preview-fps 15 \
  --overlay-alpha 0.5

Left wrist preview: http://127.0.0.1:8091. Align the gripper and fixed structures to the saved image.左腕预览地址：http://127.0.0.1:8091。对齐夹爪与固定结构。

6 · Review and retain the evidence6 · 复核并保存检查结果

Check results belong in outputs/camera_check/. The scripts provide image comparisons and alignment JSON when a comparison is saved. Inspect feature matching failures and residual overlay errors before proceeding.检查结果写入 outputs/camera_check/。保存对比时，脚本会输出对比图与对齐 JSON。开始实验前，应检查特征匹配失败和残余双影。

Current check behavior当前检查行为

Use image overlays and feature matching to check camera alignment. Inspect fixed structures for ghosting and review the saved comparison images and alignment JSON.通过参考图叠加与特征匹配检查相机对齐。检查固定结构是否存在双影，并复核保存的对比图与对齐 JSON。

  • Four calibration IDs match the connected arms, and the H pose has been checked.四个标定 ID 与实际机械臂对应，H 位已验证。
  • All three cameras use 640 × 480, 30 fps and MJPG; the saved per-camera image controls are applied and manual modes verified.三台相机均使用 640 × 480、30 fps 与 MJPG；各路已应用保存的图像参数，并核对手动模式。
  • All three live views align with their saved references at the same arm pose.三路实时画面均在相同机械臂姿态下与已有参考图对齐。
  • Reference files remain unchanged; save generated check evidence under outputs/.参考文件保持不变，生成的检查证据保存在 outputs/。

Optional · Check a replacement arm可选 · 更换机械臂后的检查

The repository provides BREE/robot_calibration/validate_replacement_arm_calibration.py. Its compare-files mode compares two calibration files without hardware. Replace both paths below with retained original and replacement calibration files; a file comparison does not establish physical pose equivalence.仓库提供 BREE/robot_calibration/validate_replacement_arm_calibration.py。其中 compare-files 可在不连接硬件时比较两份标定文件。将下方路径替换为保留的原臂与替换臂标定文件；文件比较不能直接证明实际姿态一致。

bash
python BREE/robot_calibration/validate_replacement_arm_calibration.py compare-files \
  --reference-calibration PATH_TO_ORIGINAL.json \
  --candidate-calibration PATH_TO_REPLACEMENT.json

For pose profiles, fixture checks and physical validation, follow the replacement-arm section in BREE/docs/README.md. Preserve the original calibration and reference profile before swapping hardware.参考姿态记录、夹具检查与实物验证见 BREE/docs/README.md 的替换机械臂章节。更换硬件前先保留原标定与参考姿态文件。
