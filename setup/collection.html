Data Collection数据采集

Check the bimanual teleoperation loop, restore the task scene, then record synchronized arm and camera streams with lerobot-record.确认双臂遥操作链路，恢复任务场景，再通过 lerobot-record 录制同步的机械臂与相机数据。

Run the commands below from the BREE-v1 repository root.以下命令均在 BREE-v1 仓库根目录运行。

1 · Prepare a scene reference1 · 准备场景参考图

Create your task reference directory before recording. In directory mode, use pic1.jpg, pic2.jpg and so on; a single image path can also be used. This directory is a suggested layout, not a bundled task asset.录制前创建本任务的参考图目录。目录模式使用 pic1.jpg、pic2.jpg 等连续命名，也可直接指定单张图片路径。下列结构是建议布局，并非仓库已附带的任务资源。

text
BREE/camera_reference/tasks/YOUR_TASK/
├── pic1.jpg
├── pic2.jpg
└── pic3.jpg

2 · Verify teleoperation2 · 验证遥操作

First restore the saved per-camera image controls and check 640 × 480, 30 fps and MJPG as described in Camera parameters. Verify the settings again after starting the camera streams.先按相机参数统一恢复各路保存的图像参数，并核对 640 × 480、30 fps 与 MJPG。启动视频流后再次检查参数。

bash
lerobot-teleoperate \
  --robot.type=bi_so_follower \
  --robot.id=follower_arm \
  --robot.left_arm_config.port=/dev/ttyACM0 \
  --robot.right_arm_config.port=/dev/ttyACM1 \
  --robot.left_arm_config.use_degrees=true \
  --robot.right_arm_config.use_degrees=true \
  --robot.left_arm_config.cameras="{global: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --robot.right_arm_config.cameras="{wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --teleop.type=bi_so_leader \
  --teleop.id=leader_arm \
  --teleop.left_arm_config.port=/dev/ttyACM2 \
  --teleop.right_arm_config.port=/dev/ttyACM3 \
  --teleop.left_arm_config.use_degrees=true \
  --teleop.right_arm_config.use_degrees=true \
  --fps=30 \
  --display_data=true

Confirm both leader–follower pairs, joint directions, action units and all camera views. Stop this process before running the recorder.检查两组主从臂对应关系、关节方向、动作单位和所有相机画面。启动录制前先停止遥操作进程。

3 · Record episodes3 · 录制回合

Replace YOUR_NAME/YOUR_DATASET, YOUR TASK DESCRIPTION and YOUR_TASK. Choose episode count and timing for your task. Set camera indices from the live device check.替换 YOUR_NAME/YOUR_DATASET、YOUR TASK DESCRIPTION 与 YOUR_TASK。按任务设置回合数与时间，并根据设备检查结果填写相机编号。

Note说明

For this revision, keep path-valued scene options in a JSON configuration to avoid the command parser issue documented in the evaluation section. The following prepares a recording configuration from the repository’s hardware template, clears its policy, and uses the collection settings in the operating guide.本版本将场景路径选项放入 JSON 配置，以避开评测章节记录的命令解析问题。以下使用仓库中的硬件模板生成录制配置，清除策略，并采用操作指南的数据采集设置。

bash
python - <<'PY'
import json
from pathlib import Path

config = json.loads(Path("BREE/configs/xvla_eval.json").read_text())
config["policy"] = None
config["teleop"] = {
    "type": "bi_so_leader",
    "id": "leader_arm",
    "left_arm_config": {"port": "/dev/ttyACM2", "use_degrees": True},
    "right_arm_config": {"port": "/dev/ttyACM3", "use_degrees": True},
}
config["dataset"].update({
    "repo_id": "YOUR_NAME/YOUR_DATASET",
    "single_task": "YOUR TASK DESCRIPTION",
    "num_episodes": 50,
    "episode_time_s": 60,
    "reset_time_s": 40,
    "push_to_hub": False,
    "rename_map": {},
})
config.update({
    "scene_reference": "BREE/camera_reference/tasks/YOUR_TASK",
    "scene_reference_camera": "global",
    "scene_overlay_alpha": 0.4,
    "episodes_per_reference": 1,
    "scene_reference_cycle": False,
    "evaluation_seed": None,
    "scene_home_requires_h": True,
    "require_leader_home_alignment": True,
    "leader_home_tolerance": 8,
})
Path("outputs/record").mkdir(parents=True, exist_ok=True)
Path("outputs/record/collect.json").write_text(json.dumps(config, indent=2) + "\n")
PY

Edit outputs/record/collect.json before running. It starts from global / left wrist / right wrist 0 / 2 / 4; update all ports, camera indices, dataset name, task prompt and scene path. In directory mode, provide enough numbered images for the selected episode count or deliberately enable scene_reference_cycle.运行前编辑 outputs/record/collect.json，初始相机映射为全局 / 左腕 / 右腕 0 / 2 / 4。核对串口、相机编号、数据集名、任务指令与场景路径。目录模式需要准备足够的连续编号图片，或按实验设计启用 scene_reference_cycle。

bash
HF_HUB_DISABLE_XET=1 lerobot-record \
  --config_path=outputs/record/collect.json

The recorder shows a scene overlay before each episode. With this configuration, press H to return home before arranging the scene; Enter starts recording once home alignment is satisfied. Recordings remain local because dataset.push_to_hub=false.录制器会在每回合前显示场景叠加。此配置下，先按 H 回 H 位再整理场景，满足主从臂姿态对齐后按 Enter 开始。dataset.push_to_hub=false 表示录制数据仅保存在本地。

4 · Check the recorded data4 · 复核录制数据

  • Check the recorded episode count, task text and synchronized videos before training.训练前核对已录回合数、任务文本与同步视频。
  • The raw camera keys are observation.images.left_global, observation.images.left_wrist and observation.images.right_wrist.原始相机键为 observation.images.left_global、observation.images.left_wrist 与 observation.images.right_wrist。
  • Keep degree-based states/actions consistent with training and inference. Retain the configuration, source revision and reference images.保持状态与动作的角度单位在采集、训练和推理间一致，并保存配置、源码版本和参考图。

5 · Train a policy5 · 模型训练

After reviewing the dataset, select a model-specific recipe. Retain the 12-dimensional degree-based state/action convention, three camera keys and task prompt used during collection. Dataset preparation and model dependencies differ by policy.复核数据后，按模型选择训练流程。保留采集时的 12 维角度制状态 / 动作、三路相机键及任务指令。不同策略的数据准备与模型依赖各不相同。

Policy / recipe策略 / 流程Preparation准备事项
ACT ↗12-D state/actions, original camera keys; README recipe: 20,000 steps, batch 8.12 维状态 / 动作，沿用原相机键；README 示例为 20,000 步、batch 8。
SmolVLA ↗Prepare models/smolvla_robotwin and edit BREE/configs/smolvla_train.json; map cameras to camera1/2/3. Set both YOUR_RUN fields and the dataset ID.准备 models/smolvla_robotwin，编辑 BREE/configs/smolvla_train.json；相机映射为 camera1/2/3。修改两处 YOUR_RUN 与数据集 ID。
XVLA ↗Prepare lerobot/xvla-base; use action_mode=auto for the real 12-D actions and map cameras to image/image2/image3.准备 lerobot/xvla-base；使用 action_mode=auto 处理真实 12 维动作，相机映射为 image/image2/image3。
RDT ↗Convert LeRobot data to HDF5. Prepare RDT, SigLIP, T5 weights and the RDT Python environment; select the task profile.先将 LeRobot 数据转换为 HDF5，准备 RDT、SigLIP、T5 权重及 RDT Python 环境，并选择任务 profile。
OpenPI ↗Prepare LeRobot v2.1 data, pi05 base weights and normalization statistics; run the one-step smoke mode before train.准备 LeRobot v2.1 数据、pi05 基础权重和归一化统计；先执行单步 smoke，再执行 train。

ACT · prepare a run configurationACT · 准备训练配置

Create a JSON configuration so optional output paths and camera maps stay out of the affected command-line parser. Replace the dataset ID and run name before training. Use a new output directory for a new run.使用 JSON 配置保存输出路径与相机映射，避开本版本相关命令行解析问题。训练前替换数据集 ID 与运行名称；新实验使用新的输出目录。

bash
python - <<'PY'

config = {
    "dataset": {"repo_id": "YOUR_NAME/YOUR_DATASET", "video_backend": "pyav"},

    "output_dir": "outputs/train/ACT/YOUR_RUN",
    "job_name": "YOUR_RUN",
    "rename_map": {},
    "batch_size": 8,
    "num_workers": 4,
    "steps": 20000,
    "save_checkpoint": True,
    "save_freq": 5000,
    "log_freq": 100,
    "tolerance_s": 0.05,
    "wandb": {"enable": False},
}
Path("outputs/configs").mkdir(parents=True, exist_ok=True)
Path("outputs/configs/act_train.json").write_text(json.dumps(config, indent=2) + "\n")
PY
HF_HUB_DISABLE_XET=1 lerobot-train --config_path=outputs/configs/act_train.json

For a dataset outside the default LeRobot cache, set dataset.root in the training JSON to its actual local directory; keep dataset.repo_id as the dataset identity. The JSON equivalent of the README’s --dataset.root option avoids introducing another path-valued command-line override.数据集不在默认 LeRobot 缓存时，在训练 JSON 中将 dataset.root 设为实际本地目录，dataset.repo_id 仍保留数据集标识。这对应 README 的 --dataset.root 选项，并避免再增加路径类命令行覆盖参数。

Change repo_id and run_name in the generator, then run the generated JSON with the full README policy settings. bash

Training parameters · what to change训练参数 · 修改位置与作用

Parameter参数Use用法
repo_id / run_nameDataset identity and experiment name; choose a fresh output directory for each new run.数据集标识与实验名称；新实验使用未占用的输出目录。
--config_path / --policy.pathLoad the run JSON / the pretrained model. Keep rename_map at the training JSON top level.分别加载训练 JSON / 预训练模型。训练用 rename_map 位于 JSON 顶层。
batch_size / num_workers / stepsSamples per batch / data-loader workers / total training steps. Reduce batch_size when GPU memory is insufficient.每批样本数 / 数据加载进程数 / 总训练步数。显存不足时降低 batch_size。
chunk_size / n_action_stepsPrediction horizon / number of actions used from a chunk. SmolVLA uses 50/50 here; XVLA uses 30/30.预测动作段长度 / 每段使用动作数。此处 SmolVLA 为 50/50，XVLA 为 30/30。
max_state_dim / max_action_dimModel padding limits. SmolVLA uses 32/32; XVLA uses 20/20 with action_mode=auto for the 12-D robot.模型填充上限。SmolVLA 为 32/32；XVLA 为 20/20，并用 action_mode=auto 适配 12 维机械臂。
resize_imgs_with_padding / num_image_viewsInput image size and number of views: SmolVLA 512×512; XVLA 224×224 with three cameras.输入图像尺寸与视角数：SmolVLA 为 512×512；XVLA 为 224×224、三路相机。
freeze_* / train_*Select frozen encoders and trainable policy modules. These commands follow the README fine-tuning scope.选择冻结的编码器与参与训练的策略模块；此处沿用 README 的微调范围。
optimizer_* / scheduler_*SmolVLA learning rate, weight decay, warmup and decay schedule; the explicit values above reproduce the README recipe.SmolVLA 的学习率、权重衰减、预热与衰减计划；上方显式数值采用 README 示例。
use_amp / dtype / deviceMixed precision, XVLA bfloat16 and CUDA placement; confirm GPU support.混合精度、XVLA bfloat16 与 CUDA 设备设置；需确认 GPU 支持。
save_freq / log_freq / tolerance_sCheckpoint interval / logging interval / timestamp matching tolerance in seconds.checkpoint 保存间隔 / 日志间隔 / 时间戳匹配容差（秒）。
push_to_hub / wandb.enableThese examples disable model upload and W&B logging.这些示例关闭模型上传与 W&B 日志。

All training commands run from the BREE-v1 root. The scripts only generate JSON until lerobot-train is invoked. For an entirely cached VLA run, set HF_HUB_OFFLINE=1 and TRANSFORMERS_OFFLINE=1 before lerobot-train.所有训练命令均从 BREE-v1 根目录运行。生成脚本只写 JSON，执行 lerobot-train 后才开始训练。VLA 模型和数据均已缓存时，可在 lerobot-train 前设置 HF_HUB_OFFLINE=1 与 TRANSFORMERS_OFFLINE=1 完全离线运行。

RDT / OpenPI · training entry pointsRDT / OpenPI · 训练入口

The following examples use repository task/profile names, which differ from this website’s 3DAssets task numbers. Match the dataset and instruction before running. Base weights, training data and the RDT environment must be supplied separately.以下使用仓库任务 / profile 名称，与本站 3DAssets 编号不同；运行前按数据集与指令核对。基础权重、训练数据与 RDT 环境需另外准备。

bash
BREE/model_training/rdt/convert_dataset.sh \
  yyyyyy0604/task08_cylinder_insertion_50 \
  PATH_TO_LOCAL_LEROBOT_DATASET
GPU=0 BREE/model_training/rdt/train_rdt.sh \
  task08_insertion_170m \
  task08_cylinder_insertion_50 \
  "Pick up the red cylinder with the right arm, then place the blue cylinder onto the red cylinder with the left arm"

Activate the RDT environment first or set RDT_PYTHON to its interpreter. OpenPI training reads datasets/openpi/ and models/openpi/pi05_base/params/. When converting RDT HDF5 data, use convert_from_rdt_hdf5.sh and compute_norm_stats.sh as documented in BREE/model_training/README.md.先激活 RDT 环境，或用 RDT_PYTHON 指定解释器。OpenPI 训练默认读取 datasets/openpi/ 与 models/openpi/pi05_base/params/。从 RDT HDF5 转换数据时，按 BREE/model_training/README.md 使用 convert_from_rdt_hdf5.sh 与 compute_norm_stats.sh。

For the RDT conversion, replace PATH_TO_LOCAL_LEROBOT_DATASET with the local dataset directory. The converter also accepts only the dataset ID when files are already under datasets/lerobot/USER/DATASET. The three train_rdt.sh arguments are the profile, HDF5 directory name and exact language instruction. GPU selects the physical card; RDT_PYTHON can select a separate interpreter.RDT 转换命令中的 PATH_TO_LOCAL_LEROBOT_DATASET 替换为本地数据集目录；若数据已位于 datasets/lerobot/USER/DATASET，可省略该参数。train_rdt.sh 的三个位置参数依次为 profile、HDF5 目录名和完整任务指令。GPU 选择物理显卡，RDT_PYTHON 可指定独立解释器。

OpenPI · convert data and compute statisticsOpenPI · 转换数据与计算统计

For repository task01, convert its prepared RDT HDF5 directory to LeRobot v2.1 and compute the task configuration’s normalization statistics. Change both the dataset ID and config name together for another task. INPUT_DIR is the source directory; REPO_ID determines the output under datasets/openpi/.以仓库 task01 为例，将已准备的 RDT HDF5 目录转换为 LeRobot v2.1，再计算任务配置的归一化统计。切换任务时同步修改数据集 ID 与配置名。第一个参数为源目录，第二个参数决定 datasets/openpi/ 下的输出位置。

bash
BREE/model_training/openpi/convert_from_rdt_hdf5.sh \
  datasets/rdt_hdf5/task01_pickplace_big_50 \
  yyyyyy0604/task01_pickplace_big_50
BREE/model_training/openpi/compute_norm_stats.sh pi05_biso_task01

GPU_IDS selects the physical GPUs for OpenPI. The first train_openpi.sh argument is its config name; smoke runs one step and train starts a full run. Standard tasks use 30,000 steps, while the documented long-prompt, wrist-swapped and switch variants use 20,000. TRAIN_STEPS overrides this count.GPU_IDS 选择 OpenPI 使用的物理显卡。train_openpi.sh 的第一个参数为配置名；smoke 执行 1 步，train 执行完整训练。标准任务为 30,000 步，文档列出的 long-prompt、wrist-swapped 和 switch 变体为 20,000 步；TRAIN_STEPS 可覆盖步数。

bash
GPU_IDS=0,1 BREE/model_training/openpi/train_openpi.sh pi05_biso_task01 smoke
GPU_IDS=0,1 BREE/model_training/openpi/train_openpi.sh pi05_biso_task01 train

New training outputs go under outputs/train/. RDT defaults to 25,000 steps with checkpoints every 5,000; standard OpenPI tasks default to 30,000 steps and some variants use 20,000. To resume, use RESUME=1 with the same RDT output directory or the same OpenPI EXP_NAME. Save the training configuration and use the actual generated checkpoint path in evaluation.新训练结果写入 outputs/train/。RDT 默认 25,000 步、每 5,000 步保存；OpenPI 标准任务默认 30,000 步，部分变体为 20,000 步。恢复训练时使用 RESUME=1，并保持 RDT 输出目录或 OpenPI EXP_NAME 与原实验一致。保存训练配置，评测时填写实际生成的 checkpoint 路径。

Resume RDT / OpenPI training恢复 RDT / OpenPI 训练

Resume the same experiment, using its original output directory and settings. For OpenPI, replace my_test with the EXP_NAME used when starting that run. For RDT, keep PROFILE, dataset and instruction unchanged; preserve any OUTPUT_DIR or RDT_PYTHON override from the initial run.恢复同一实验时，沿用原输出目录与配置。OpenPI 的 my_test 要替换为最初启动时使用的 EXP_NAME。RDT 保持 profile、数据集和指令不变，并沿用首次运行时设置的 OUTPUT_DIR 或 RDT_PYTHON。
