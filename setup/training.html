10. Model training10. 模型训练

Run all commands below from ../lerobot. Before training, replace YOUR_NAME/YOUR_DATASET and YOUR_RUN, and confirm that the new output directory does not already exist so that new results remain separate from previous training runs.以下命令都从 ../lerobot 运行。开始训练前需要修改 YOUR_NAME/YOUR_DATASET 和 YOUR_RUN，并确认新的输出目录不存在，避免与以前的训练结果混在一起。

10.1 ACT training10.1 ACT 训练

ACT can directly read the current bimanual dataset's 12-dimensional states, 12-dimensional actions and three original camera keys. Camera keys do not need to be renamed.ACT 可以直接读取当前双臂数据集中的 12 维状态、12 维动作以及三个原始相机键，不需要进行相机键重命名。

bash
HF_HUB_DISABLE_XET=1 lerobot-train \
  --dataset.repo_id=YOUR_NAME/YOUR_DATASET \
  --dataset.video_backend=pyav \
  --policy.type=act \
  --policy.device=cuda \
  --policy.use_amp=true \
  --policy.push_to_hub=false \
  --output_dir=outputs/train/ACT/YOUR_RUN \
  --job_name=YOUR_RUN \
  --batch_size=8 \
  --num_workers=4 \
  --steps=20000 \
  --save_checkpoint=true \
  --save_freq=5000 \
  --log_freq=100 \
  --tolerance_s=0.05 \
  --wandb.enable=false

These are the main settings used by the existing models in outputs/train/ACT/: AMP, batch size 8, 4 data-loading workers, 20000 training steps and a checkpoint every 5000 steps. ACT uses 100-step action chunks by default. If you change this, also check the data length and the action-execution settings used for real-robot evaluation.这与当前 outputs/train/ACT/ 中已有模型使用的主要参数一致：AMP、batch size 8、4 个数据读取进程、训练 20000 步、每 5000 步保存一次。ACT 默认使用 100 步 action chunk；如需改变，必须同时确认数据长度和实机评估时的动作执行设置。

If the dataset is outside Hugging Face's default LeRobot cache location, you can also add:如果数据集不在 Hugging Face 的默认 LeRobot 缓存位置，可以额外增加：

text
--dataset.root=/实际的数据集目录

10.2 SmolVLA training10.2 SmolVLA 训练

The existing task01–task08 models were fine-tuned from the RoboTwin-pretrained models/smolvla_robotwin. The following command follows the train_config.json files saved with the existing models.现有 task01～task08 模型是从 RoboTwin 预训练的 models/smolvla_robotwin 继续微调。以下命令按照现有模型保存的 train_config.json 整理。

bash
HF_HUB_DISABLE_XET=1 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
lerobot-train \
  --config_path=BREE/configs/smolvla_train.json \
  --dataset.repo_id=YOUR_NAME/YOUR_DATASET \
  --dataset.video_backend=pyav \
  --policy.path=models/smolvla_robotwin \
  --policy.device=cuda \
  --policy.use_amp=true \
  --policy.push_to_hub=false \
  --policy.chunk_size=50 \
  --policy.n_action_steps=50 \
  --policy.max_state_dim=32 \
  --policy.max_action_dim=32 \
  --policy.resize_imgs_with_padding='[512, 512]' \
  --policy.freeze_vision_encoder=true \
  --policy.train_expert_only=true \
  --policy.train_state_proj=true \
  --policy.optimizer_lr=0.0001 \
  --policy.optimizer_weight_decay=1e-10 \
  --policy.scheduler_warmup_steps=1000 \
  --policy.scheduler_decay_steps=20000 \
  --policy.scheduler_decay_lr=2.5e-6 \
  --batch_size=12 \
  --num_workers=4 \
  --steps=30000 \
  --save_checkpoint=true \
  --save_freq=5000 \
  --log_freq=500 \
  --tolerance_s=0.05 \
  --wandb.enable=false

The existing SmolVLA task models share these settings: three cameras, 12-dimensional real actions, 50-step action chunks, maximum state and action dimensions of 32, images padded to 512×512, a frozen vision encoder, and training of the expert and state projection. The three-camera rename_map is already defined in BREE/configs/smolvla_train.json.现有 SmolVLA 任务模型的共同配置为：三个相机、12 维真实动作、50 步 action chunk、状态和动作最大维度 32、图像 padding 到 512×512、冻结视觉编码器，并训练 expert 与 state projection。三个相机的 rename_map 已写在 BREE/configs/smolvla_train.json 中。

You must use --config_path here: the command-line configuration parser used in this repository cannot correctly parse the top-level --rename_map dictionary or the optional path type of --output_dir; passing them directly on the command line causes parameter-type errors. Before training, replace YOUR_NAME/YOUR_DATASET in the command with the actual dataset, then open BREE/configs/smolvla_train.json and replace both occurrences of YOUR_RUN with the training-run name. The command-line --dataset.repo_id overrides the dataset placeholder in the configuration template.这里必须使用 --config_path：当前仓库所用的命令行配置解析器不能正确解析顶层 --rename_map 字典以及可选路径类型的 --output_dir，直接在命令中传入会报参数类型错误。训练前需要修改两处：将命令中的 YOUR_NAME/YOUR_DATASET 换成真实数据集；将 BREE/configs/smolvla_train.json 中两处 YOUR_RUN 换成训练名称。命令中的 --dataset.repo_id 会覆盖配置模板里的数据集占位值。

10.3 XVLA training10.3 XVLA 训练

The XVLA base model uses image, image2 and image3 as its three visual-input keys, so the current dataset's global, left-wrist and right-wrist camera keys must be renamed. action_mode=auto automatically identifies the bimanual dataset's 12-dimensional real actions and applies padding and trimming within XVLA's 20-dimensional model action space.XVLA 基础模型使用 image、image2、image3 作为三个视觉输入键，因此必须把当前数据集的全局、左腕和右腕相机键重命名。action_mode=auto 会根据双臂数据集自动识别真实的 12 维动作，并在 XVLA 的 20 维模型动作空间中完成填充和裁剪。

The settings below follow existing XVLA training results on this machine: 3 cameras, 30-step action chunks, bfloat16, batch size 2, and training of the policy transformer and soft prompts.下面的参数根据本机已有 XVLA 训练结果整理：使用 3 个相机、30 步 action chunk、bfloat16、batch size 2，并训练 policy transformer 和 soft prompts。

bash
HF_HUB_DISABLE_XET=1 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
lerobot-train \
  --dataset.repo_id=YOUR_NAME/YOUR_DATASET \
  --dataset.video_backend=pyav \
  --policy.path=lerobot/xvla-base \
  --policy.device=cuda \
  --policy.use_amp=true \
  --policy.push_to_hub=false \
  --policy.dtype=bfloat16 \
  --policy.action_mode=auto \
  --policy.max_state_dim=20 \
  --policy.max_action_dim=20 \
  --policy.chunk_size=30 \
  --policy.n_action_steps=30 \
  --policy.resize_imgs_with_padding='[224, 224]' \
  --policy.num_image_views=3 \
  --policy.freeze_vision_encoder=true \
  --policy.freeze_language_encoder=true \
  --policy.train_policy_transformer=true \
  --policy.train_soft_prompts=true \
  --rename_map='{
    "observation.images.left_global": "observation.images.image",
    "observation.images.left_wrist": "observation.images.image2",
    "observation.images.right_wrist": "observation.images.image3"
  }' \
  --output_dir=outputs/train/XVLA/YOUR_RUN \
  --job_name=YOUR_RUN \
  --batch_size=2 \
  --num_workers=2 \
  --steps=30000 \
  --save_checkpoint=true \
  --save_freq=5000 \
  --log_freq=500 \
  --tolerance_s=0.05 \
  --wandb.enable=false

The current command freezes XVLA's vision and language encoders and trains only the policy Transformer and soft prompts, keeping GPU memory use relatively low. To fine-tune the full VLM, set both freeze parameters to false, but expect substantially higher memory use and training time.当前命令冻结 XVLA 的视觉和语言编码器，只训练策略 Transformer 和 soft prompts，显存占用相对较低。如果需要完整微调 VLM，可以把两个 freeze 参数改成 false，但显存和训练时间都会明显增加。

Before the first training run, confirm that the XVLA extra dependencies are installed and that lerobot/xvla-base can be downloaded from Hugging Face or is already cached locally. The base model on the current machine is cached at:首次训练前确认已安装 XVLA 额外依赖，并且 lerobot/xvla-base 可以从 Hugging Face 下载或已经存在于本机缓存中。当前机器的基础模型已经缓存在：

text
~/.cache/huggingface/hub/models--lerobot--xvla-base/

If all models and data are cached and you need fully offline training, you can also set the following at the start of the command:如果确认所有模型和数据都已缓存，需要完全离线训练时，可以在命令开头额外设置：

text
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1

10.4 RDT and OpenPI training10.4 RDT 与 OpenPI 训练

The RDT and OpenPI training functionality is organized under:RDT 和 OpenPI 训练功能已经整理到：

text
BREE/model_training/

By default, training scripts read their dependencies from models/ and datasets/ in the current LeRobot repository and write checkpoints to outputs/train/.训练脚本默认从当前 LeRobot 仓库下的 models/ 和 datasets/ 读取依赖，并将 checkpoint 写入 outputs/train/。

10.4.1 OpenPI training10.4.1 OpenPI 训练

OpenPI reads data from datasets/openpi/ and base weights from models/openpi/pi05_base/params/ by default, and saves checkpoints to outputs/train/OpenPI/. For the first run, start with a 1-step smoke test:OpenPI 默认读取 datasets/openpi/ 下的数据和 models/openpi/pi05_base/params/ 下的基础权重，并把 checkpoint 保存到 outputs/train/OpenPI/。第一次训练建议先执行 1 步 smoke test：

bash
GPU_IDS=0,1 \
BREE/model_training/openpi/train_openpi.sh pi05_biso_task01 smoke

After confirming that the data, weights, GPUs, FSDP and checkpoint writing work correctly, start a full training run:确认数据、权重、GPU、FSDP 和 checkpoint 写入都正常后，再开始正式训练：

bash
GPU_IDS=0,1 \
BREE/model_training/openpi/train_openpi.sh pi05_biso_task01 train

To resume the same experiment from an existing checkpoint, EXP_NAME must match the original experiment name:需要从已有 checkpoint 恢复同一个实验时，EXP_NAME 必须与原实验名称一致：

bash
GPU_IDS=0,1 RESUME=1 EXP_NAME=my_test \
BREE/model_training/openpi/train_openpi.sh pi05_biso_task03_switch_new train

If you currently have only the HDF5 data used by RDT, first convert it to the LeRobot v2.1 format used by OpenPI, then compute normalization statistics:如果当前只有 RDT 使用的 HDF5 数据，先转换成 OpenPI 使用的 LeRobot v2.1 数据，再计算归一化统计：

bash
BREE/model_training/openpi/convert_from_rdt_hdf5.sh \
  datasets/rdt_hdf5/task01_pickplace_big_50 \
  yyyyyy0604/task01_pickplace_big_50

BREE/model_training/openpi/compute_norm_stats.sh pi05_biso_task01

Here, GPU_IDS selects the physical GPUs used for training; the first positional argument is the OpenPI training configuration name; smoke trains for only 1 step, while train starts full training; and RESUME=1 resumes training. Standard tasks train for 30000 steps by default, while some long-prompt, wrist-swapped and switch variants default to 20000 steps. Override this with TRAIN_STEPS=步数.其中 GPU_IDS 指定参与训练的物理 GPU；第一个位置参数是 OpenPI 训练配置名；smoke 只训练 1 步，train 执行正式训练；RESUME=1 表示恢复训练。标准任务默认训练 30000 步，部分 long-prompt、wrist-swapped 和 switch 变体默认训练 20000 步，可用 TRAIN_STEPS=步数 覆盖。

10.4.2 RDT training10.4.2 RDT 训练

RDT reads data from datasets/rdt_hdf5/ and the RDT, SigLIP and T5 weights from models/rdt/ by default, and saves checkpoints to outputs/train/RDT/. If you currently have only LeRobot data, convert it first:RDT 默认读取 datasets/rdt_hdf5/ 下的数据和 models/rdt/ 下的 RDT、SigLIP、T5 权重，并把 checkpoint 保存到 outputs/train/RDT/。如果目前只有 LeRobot 数据，先执行转换：

bash
BREE/model_training/rdt/convert_dataset.sh \
  yyyyyy0604/task08_cylinder_insertion_50

Then start a full training run. RDT_PYTHON must point to a Python interpreter with the RDT dependencies installed. You can omit this variable if those dependencies are already installed correctly in the current environment:然后执行正式训练。RDT_PYTHON 要指向已经安装 RDT 依赖的 Python；如果当前环境已经正确安装依赖，也可以省略这个变量：

bash
GPU=0 \
RDT_PYTHON=/实际的/rdt环境/bin/python \
BREE/model_training/rdt/train_rdt.sh \
  task08_insertion_170m \
  task08_cylinder_insertion_50 \
  "Pick up the red cylinder with the right arm, then place the blue cylinder onto the red cylinder with the left arm"

Resume an existing training run:恢复已有训练：

bash
GPU=0 RESUME=1 \
RDT_PYTHON=/实际的/rdt环境/bin/python \
BREE/model_training/rdt/train_rdt.sh \
  task08_insertion_170m \
  task08_cylinder_insertion_50 \
  "Pick up the red cylinder with the right arm, then place the blue cylinder onto the red cylinder with the left arm"

The three positional arguments are, in order: the task profile, the data-directory name under datasets/rdt_hdf5/, and the task's language instruction. GPU selects the physical GPU, and RESUME=1 resumes from an existing checkpoint in the output directory. By default, training runs for 25000 steps and saves a checkpoint every 5000 steps. Change these with MAX_TRAIN_STEPS and CHECKPOINT_PERIOD, respectively.三个位置参数依次为：任务 profile、datasets/rdt_hdf5/ 下的数据目录名、任务语言指令。GPU 指定物理 GPU，RESUME=1 表示从输出目录中的已有 checkpoint 恢复。默认训练 25000 步、每 5000 步保存一次，可分别用 MAX_TRAIN_STEPS 和 CHECKPOINT_PERIOD 修改。

The training code has been merged into BREE, but the code directory does not include the base models, training data or RDT Python environment. Before training, place them in the default directories above or use the environment variables supported by the training scripts to point to their actual locations.训练代码已经合并进 BREE，但基础模型、训练数据和 RDT Python 环境没有包含在代码目录中；开始训练前必须把它们放入上述默认目录，或使用训练脚本支持的环境变量指向实际位置。

For the complete list of configuration names, RDT profiles, installation dependencies and overridable paths, see:完整的配置名称、RDT profile、安装依赖以及所有可覆盖路径见：

text
BREE/model_training/README.md

The complete contents of BREE/model_training/README.md follow.下方完整展开 BREE/model_training/README.md 的内容。

BREE model trainingBREE 模型训练

This directory contains only the RDT and OpenPI training entry points, task configurations and data-conversion tools. Runtime files, language embeddings and checkpoints generated during training are written to outputs/ at the repository root, rather than to BREE.本目录只保存 RDT 和 OpenPI 的训练入口、任务配置与数据转换工具。训练产生的 runtime、语言向量和 checkpoint 统一写入仓库根目录的 outputs/，不会写入 BREE。

Environment variables can override the default locations for models or data stored on external disks.所有启动脚本都会根据自身位置查找 /home/l/lerobot 仓库根目录，不依赖原服务器的 /home/yanch/...。外部磁盘上的模型或数据可以通过环境变量覆盖默认位置。

The default parameters match the server's standard 170M training setup: 25000 steps, batch size 2, gradient accumulation of 4, global batch size 8, learning rate 1e-4, and a checkpoint every 5000 steps.默认参数与服务器标准 170M 训练一致：25000 步、batch size 2、梯度累积 4、全局 batch 8、学习率 1e-4、每 5000 步保存。

Profiles with 1b in their names load rdt-1b by default; the others load rdt-170m.其中 long-prompt、wrist-swapped、switch-new、switch-right 和 task04 masked-loss profile 使用 masked loss，只让真实机器人动作维度参与 loss；其余 profile 使用标准 MSE。名称包含 1b 的 profile 默认加载 rdt-1b，其他默认加载 rdt-170m。

3. Files not included3. 未包含的文件
