Running Evaluations运行评估

Use the policy-specific JSON configuration to record real-robot evaluation episodes. The current templates use 20 episodes, a 120-second limit and seeds grouped in sets of five saved episodes.使用策略对应的 JSON 配置录制真机评测回合。当前模板为 20 回合、每回合最长 120 秒，并以每 5 个已保存回合为一组设置 seed。

Run the commands below from the BREE-v1 repository root.以下命令均在 BREE-v1 仓库根目录运行。

Before you evaluate评测之前

Verify the H pose, all three reference overlays, camera order and action units first. These LeRobot evaluation commands can move the arms; they are not dry runs. Prepare the checkpoint and scene images before starting.先验证 H 位、三路参考图叠加、相机顺序与动作单位。以下 LeRobot 评测命令会驱动机械臂，并非 dry-run；启动前准备好模型权重与场景参考图。

3 · ID / OOD scenes and operation3 · ID / OOD 场景与操作

ID (in-distribution) evaluates scenes drawn from the conditions covered by training. OOD (out-of-distribution) evaluates a specified held-out condition. The diagrams below illustrate a change in starting position while the task and target stay the same.ID（分布内）评测训练数据覆盖的场景条件，OOD（分布外）评测指定的未见条件。下图以初始摆放位置变化为例，任务与目标位置保持一致。

Conceptual diagrams, not benchmark reference images. The shaded dashed area represents training layout coverage; blocks 1 and 2 are the manipulated objects. These drawings do not specify official positions, distances or an OOD threshold. Use the designated task scene images for the actual evaluation conditions.以上为概念示意，并非评测实景参考图。虚线阴影区表示训练布局覆盖范围，色块 1、2 表示操作物体。图中未规定正式摆放坐标、距离或 OOD 阈值；实际评测条件以指定任务的场景图为准。

B · Prepare matched image setsB · 准备配对场景图

Use the supplied ID directory for the chosen task. When its OOD reference set is available, place those images in a sibling OOD directory and number each set pic1, pic2, and so on. The recorder accepts JPG, JPEG, PNG and WebP. Use the same numbered scene pairs for each policy comparison.使用所选任务随仓库提供的 ID 目录。取得对应 OOD 参考集后，将其放在同级 OOD 目录，并各自按 pic1、pic2 等连续编号。录制器支持 JPG、JPEG、PNG 和 WebP；不同策略的比较应使用同一组编号配对场景。

text
outputs/id_ood_benchmark_pairs/YOUR_TASK/
├── ID/
│   ├── pic1.jpg
│   ├── pic2.jpg
│   └── ...
└── OOD/
    ├── pic1.jpg
    ├── pic2.jpg
    └── ...

Choose the OOD condition before running trials and record what changes relative to ID. For a position-only comparison, retain the same objects, colors, instruction, camera mounting, lighting and target definition. The actual ID/OOD split and image count belong to the task protocol.在试验前确定 OOD 条件，并记录相对 ID 改变了什么。若只评测位置变化，则保持物体、颜色、指令、相机安装、光照及目标定义一致。实际 ID/OOD 划分与图片数量由任务协议确定。

C · Create ID and optional OOD configurationsC · 生成 ID 与可选 OOD 配置

Start from the edited outputs/eval/act_run.json in step 2. In the script below, replace YOUR_TASK, YOUR_NAME and YOUR_RUN. The script defaults to ID only. Once OOD images are ready, set splits = ("ID", "OOD") to generate the matched pair. It changes only scene_reference and dataset.repo_id.以上一步编辑好的 outputs/eval/act_run.json 为基础。替换下方脚本中的 YOUR_TASK、YOUR_NAME 与 YOUR_RUN。脚本默认仅生成 ID 配置。OOD 图片准备好后，将 splits 改为 ("ID", "OOD")，即可生成配对配置。脚本仅更换 scene_reference 与 dataset.repo_id。

bash
python - <<'PY'
import copy
import json
import re
from pathlib import Path

base = json.loads(Path("outputs/eval/act_run.json").read_text())
scene_root = Path("outputs/id_ood_benchmark_pairs/YOUR_TASK")
owner = "YOUR_NAME"
run = "YOUR_RUN"
splits = ("ID",)

counts = []
for split in splits:
    folder = scene_root / split
    if not folder.is_dir():
        raise FileNotFoundError(folder)
    numbers = sorted(
        int(match.group(1))
        for image in folder.iterdir()
        if image.is_file() and image.suffix.lower() in (".jpg", ".jpeg", ".png", ".webp")
        if (match := re.fullmatch(r"pic(\d+)", image.stem))
    )
    if not numbers or numbers != list(range(1, len(numbers) + 1)):
        raise ValueError(f"{split}: expected one image per number, starting at pic1")
    counts.append(len(numbers))
if len(set(counts)) > 1:
    raise ValueError("ID and OOD must have matching numbered scene pairs")

for split in splits:
    config = copy.deepcopy(base)
    config["scene_reference"] = (scene_root / split).as_posix()
    config["dataset"]["repo_id"] = f"{owner}/eval_{run}_{split.lower()}"
    output = Path(f"outputs/eval/act_{split.lower()}.json")
    output.write_text(json.dumps(config, indent=2) + "\n")
    print(output)
PY

Use a new run name for each experiment. For SmolVLA or XVLA, begin with that policy’s edited configuration so its camera mapping is retained. Keep the checkpoint, timing, episode count and seed settings identical for the matched comparison.每次实验使用新的运行名称。SmolVLA 或 XVLA 应以各自编辑后的配置为基础，保留对应相机映射。配对比较使用相同模型权重、时间预算、回合数与 seed 设置。

D · Reset and confirm each sceneD · 逐回合复位与确认场景

  1. Run the ID configuration first using step 4 below. The recorder shows the selected reference over the live global camera image. It requires a graphical desktop and a GUI-capable OpenCV installation.按下一节命令先运行 ID 配置。录制器将所选参考图叠加到全局相机实时画面上；此预览需要图形桌面与支持 GUI 的 OpenCV。
  2. Wait for the follower arms to reach the H pose, then arrange the objects to match the reference. The current evaluation templates home automatically; if scene_home_requires_h is true, press H first.等待从臂回到 H 位，再按参考图摆放物体。当前评测模板会自动回 H 位；若 scene_home_requires_h 为 true，则先按 H。
  3. Press Enter after the scene is aligned. The policy then runs until the episode limit or an early-end key. The recorder advances references according to saved episodes.场景对齐后按 Enter 开始。策略执行至回合时间上限或提前结束操作；录制器按已保存回合数推进参考图。
  4. Record task success or failure for every trial. A failed task still counts as an evaluation trial; keep it in the results. Use the left-arrow rerecord function for recording/setup errors and log the reason.每次试验都记录任务成功或失败。任务失败仍属于评测试验，应保留在结果中；录制或场景设置错误时使用左方向键重录，并记录原因。
  5. After the ID run exits and the OOD images are available, launch the OOD configuration with the same checkpoint. Restore each OOD scene from its reference and record results in the separate OOD dataset.ID 运行结束退出且 OOD 图片已齐备后，用同一模型启动 OOD 配置。逐回合按 OOD 参考图恢复场景，结果录入独立的 OOD 数据集。

6 · RDT and OpenPI6 · RDT 与 OpenPI

RDT uses BREE/model_inference/rdt_bi_so_inference.py; see the RDT example and start with --dry-run. OpenPI uses a separate policy server and robot client; follow the OpenPI guide. Its client is read-only by default and requires --execute to send actions. Check environment, tokenizer and checkpoint availability separately.RDT 使用 BREE/model_inference/rdt_bi_so_inference.py，参照 RDT 示例 并先保留 --dry-run。OpenPI 分为策略服务端与机器人客户端，见 OpenPI 指南；客户端默认只读，需增加 --execute 才会发送动作。请单独核实环境、tokenizer 与权重是否齐全。
