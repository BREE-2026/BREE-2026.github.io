Running Evaluations 运行评估

Evaluation runs a trained policy on the calibrated rig through lerobot-record — fixed episode count, fixed time budget, fixed scene references. Because every BREE site is calibrated to the same reference, results are directly comparable. 评测通过 lerobot-record 在已标定机架上运行训练好的策略——固定回合数、固定时间预算、固定场景参考。由于所有 BREE 站点都标定到同一参考，结果可直接互相比较。

⚠ Before you evaluate ⚠ 评测之前

Re-run the AprilTag checks after any camera or arm movement. Evaluation only begins when all three cameras report within_tolerance = true and the live scene matches the task reference image. 相机或机械臂有任何移动后，必须重新执行 AprilTag 检查。只有三台相机全部报告 within_tolerance = true 且实时场景与任务参考图一致时，才能开始评测。

1 · Sanity-check teleoperation1 · 遥操作自检

Confirm the bimanual leader–follower loop and all three camera streams before touching policies: 在运行策略之前，先确认双主从臂链路与三路相机画面正常：

bash
lerobot-teleoperate \
  --robot.type=bi_so_follower --robot.id=follower_arm \
  --robot.left_arm_config.port=/dev/ttyACM0 \
  --robot.right_arm_config.port=/dev/ttyACM1 \
  --robot.left_arm_config.cameras="{global: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --robot.right_arm_config.cameras="{wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --teleop.type=bi_so_leader --teleop.id=leader_arm \
  --teleop.left_arm_config.port=/dev/ttyACM2 \
  --teleop.right_arm_config.port=/dev/ttyACM3 \
  --fps=30 --display_data=true

2 · Policy evaluation2 · 策略评测

Example — evaluating a SmolVLA checkpoint on a stacking task. The same command records the evaluation episodes as a LeRobotDataset: 示例——在某堆叠任务上评测 SmolVLA 检查点。同一条命令会把评测回合录制为 LeRobotDataset：

bash
HF_HUB_DISABLE_XET=1 lerobot-record \
  --robot.type=bi_so_follower --robot.id=follower_arm \
  --robot.left_arm_config.port=/dev/ttyACM0 \
  --robot.right_arm_config.port=/dev/ttyACM1 \
  --robot.left_arm_config.cameras="{global: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --robot.right_arm_config.cameras="{wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --teleop.type=bi_so_leader --teleop.id=leader_arm \
  --teleop.left_arm_config.port=/dev/ttyACM2 \
  --teleop.right_arm_config.port=/dev/ttyACM3 \
  --policy.path=outputs/train/<run>/checkpoints/<step>/pretrained_model \
  --policy.device=cuda --display_data=true \
  --dataset.repo_id=<your-org>/eval_<run> \
  --dataset.single_task="stack two blocks" \
  --dataset.rename_map='{
    "observation.images.left_global": "observation.images.camera1",
    "observation.images.left_wrist": "observation.images.camera2",
    "observation.images.right_wrist": "observation.images.camera3"
  }' \
  --dataset.num_episodes=10 \
  --dataset.episode_time_s=40 \
  --dataset.reset_time_s=40 \
  --dataset.push_to_hub=false

4 · Success criteria & reporting4 · 成功判据与结果上报

  • An episode is a success only if it satisfies the task's measurable criterion (see Task Reference). 只有满足任务的可度量判据（见任务参考）才算该回合成功。
  • Log success / failure per episode; report success rate over all episodes, with the checkpoint ID and date. 逐回合记录成功 / 失败；汇报全部回合的成功率，并附检查点 ID 与日期。
  • Leaderboard submission details will be announced with the paper release. 排行榜提交细节将随论文发布公布。
